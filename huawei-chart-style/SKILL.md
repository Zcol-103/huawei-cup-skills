## 工作协议

1. 先写一句图表命题：这张图要让读者比较、发现、验证还是作决策？注明对象、指标和数据范围。
2. 按数据结构选最小图集：分布/趋势、关系/空间、流程/模型、评价/敏感性分别选择相应图种；一张图只承担一个主要读者动作。
3. 先设计证据链，再写代码：描述现象 → 展示关系/机制 → 说明模型 → 验证误差或稳健性 → 输出决策。每张图的图题和正文都要指向链条中的一句结论。
4. 统一语义：同一对象跨图用同色，同一指标用同单位/尺度，同一组方案保持排序；对比图优先共享坐标范围和子图布局。
5. 导出后做视觉核验：检查字体、负号、下标、图例、长标签、裁剪、dpi、留白和色盲可辨识度；必要时渲染 PNG 后再迭代。

## 稳健默认与主动克制

- 默认白底、低饱和网格、深色文字、有限强调色；Windows 优先宋体/黑体，英文和数学符号可用 Times New Roman，确保字体实际存在。
- 论文版面通常用 1×2、2×2、2×3 子图；线宽、字号、marker 和图例以版面尺寸反推，300 dpi 只是输出下限，不是质量本身。
- 3D 仅在空间/曲面几何不可压缩时使用；雷达图仅作多维轮廓补充；饼图只用于少量互斥构成；双轴图只有在两个量纲都必要且轴语义清楚时使用。能用二维排序、趋势或散点表达时，优先二维。
- 流程图/网络结构用 SVG、PPT、draw.io 或 Visio 等矢量工具；matplotlib 主要负责数据图。

## 新情况判断

若题目、数据或论文风格不在参考范围内，执行：

`论证命题 → 数据类型 → 最小图集 → 颜色/排序/尺度约定 → 反例检查 → 渲染核验 → 图旁解释`

反例检查是：去掉阴影、3D、渐变或装饰后，结论是否仍可读？若不能，说明图在靠装饰传达信息，应重画。不要因为优秀论文出现过某种图，就机械复制。

## 交付要求

交付图表时同时给出：图种选择理由、数据预处理/尺度说明、可复现代码或编辑源、导出参数、视觉核验结果，以及该图支持的具体结论。不要只给一张“好看”的图片。
